- (direction) input is INTENT.md (Epic 1 done-when/must-not-change/out-of-scope), read alongside seed/*.csv, mcp/triage_server.py and TRIAGE_POLICY.md for grounding; input rich enough to extract directly, no elicitation
- (capability) CAP-1 triage-decision schema: a decision is a JSON object with category (billing|bug|access|performance|how-to), priority (P1-P4), route (billing-team|bug-team|access-team|performance-team|how-to-team) and a one-sentence rationale; success: a valid decision is accepted, anything else (missing/extra-out-of-set value, wrong type) is rejected with a clear error naming the problem
- (capability) CAP-2 seed loader: uv run python load_seed.py loads seed/tickets.csv and seed/customers.csv into app.db as tables tickets and customers with the same columns as the CSVs; success: after one run app.db has both tables, same column names and row counts as the CSVs (24 tickets, 20 customers)
- (capability) CAP-3 idempotent load: running load_seed.py twice gives the same database; success: a second run leaves the same tables, columns and rows, no duplicates, no error
- (constraint) Python 3.12 or newer, managed with uv
- (constraint) files in seed/ are read-only; the loader only reads them
- (constraint) no network calls and no API keys anywhere in this epic -- schema validation and loading are fully local
- (constraint) mcp/triage_server.py already reads app.db (tickets: ticket_id, customer_id, created_at, text; customers: customer_id, name, plan, open_tickets); those table and column names must keep working
- (non-goal) the agent, the MCP tools, evals and any user interface are out of scope
- (question) should the schema reject a route that does not match its category per TRIAGE_POLICY.md (e.g. billing with bug-team), or only check each field against its own allowed set? INTENT.md is silent
- (question) how strictly is 'one-sentence rationale' enforced -- non-empty string only, or rejected if it contains more than one sentence?
- (question) should open_tickets be stored as INTEGER (TRIAGE_POLICY's Enterprise rule compares it to 3) or kept as CSV text? INTENT.md says only 'same columns'
- (note) TRIAGE_POLICY.md adopted as companion: it defines the category-to-route table and the one-sentence rationale the schema encodes; mcp/triage_server.py adopted as companion: it is the consumer whose table/column names the loader must satisfy; INTENT.md listed as source (fully absorbed)
